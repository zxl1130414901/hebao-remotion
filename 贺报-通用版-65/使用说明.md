## 换成你自己行业的内容

文案全部住在 `content/demo.json`（65 条，键 `u01`–`u65`），**改文案不需要碰任何代码**。两条路选一条：

### A · 出片台（推荐，不写命令）

```bash
npm run make          # 等同 node tools/studio.mjs
```

浏览器打开 `http://127.0.0.1:8788` → 左边选模板 → 右边填 → 点「生成视频」。

- **只渲你选中的这一支**，其它 64 支原样不动，单支约 30 秒
- 表单会随版式变化：巨字/人物/数字版出「核心数字」，榜单版出「榜单行」，历程版出「三节点」
- 「存为模板文案」把当前内容写回 `content/demo.json`，下次打开就是这份
- 地址带 `?id=u26` 可直接定位某支，方便发给同事"就改这一支"
- 成片落在 `studio-out/`

### B · 命令行（批量 / 自动化）

```bash
npx remotion render src/u/index.ts u26 out/年度卓越奖.mp4 \
  --props=props.json --concurrency=6 --crf=19
```

> **为什么改文案一定要渲染、而不能"直接编辑"？**
> 成片是 mp4，文字已经烧成像素，没有文本层，改字只能重画这一帧。所以"可编辑"指的是**文案和数据可编辑**，不是成片可编辑。区别只在渲几支：改一支 = 30 秒；只有动了公共层（版式、皮肤、占位符规则）才需要全量重渲 65 支（约 30 分钟）。

## 渲染纪律

| 参数 | 值 | 说明 |
|---|---|---|
| `--concurrency` | 3–4 | 本机 22 核实测：并发 6 以上不再提速，反而更容易 OOM |
| 浏览器复用 | 每 4 支重启 | 复用 Chrome 会累积内存，跑到 8 支以上必然崩，脚本已按批重启 |
| `--crf` | 19 | 质量 / 体积平衡点 |
| 单支耗时 | 40–90s | 8s × 60fps = 482 帧，重装饰皮肤偏慢 |
| 分辨率 | 1080×1920 | 竖屏，抖音 / 视频号 / 朋友圈直接可用 |

批量：工程目录执行 `node tools/render65.mjs`（单次打包 + 分批重启浏览器，跑完 u01–u65）；`bash tools/render65.sh` 为纯串行壳，慢但最稳。

**只改文案不用清缓存、也不用全量重渲**：文案在 `content/demo.json`，出片台走 props 覆盖，只渲你选的那一支。

**改了版式 / 皮肤 / 组件才要清缓存并全量重渲**：`rm -rf node_modules/.cache/remotion node_modules/.cache/webpack`，否则视频会命中旧打包产物（静帧是新的、成片是旧的）。

## 演示内容与视觉规范（2026-11-06 修订）

这一版按四条硬规则重做了全量演示内容与底层构图，任何二次创作都应遵守：

**1. 专名一律用占位符，画面零真实信息**

演示片里不出现任何真实、或看着像真实的人名、机构、医院、商场、城市、赛事、奖项。全部换成占位符，客户一眼就知道"这一格归你填"：

| 类型 | 占位写法 | 示例 |
|---|---|---|
| 机构 / 项目 | 某某 + 行业词 | 某某科技 / 某某资本 / 某某医院 / 某某壹号 |
| 单人姓名 | 某某（保留头衔） | 某某 · 区域总监 / 某某 博士 |
| 榜单多行 | 类别 + 甲乙丙丁戊 / A–E | 门店 A / 医院 B / 选手 C / 直播间 D |
| 城市 / 场馆 | 某某市 / 某某 + 场馆；并列时用甲市–戊市 | 某某市 / 某某大剧院 / 甲市 |
| 赛事 / 奖项 | 某某联赛 / 年度大奖 | 某某联赛 S10 / 年度剧目大奖 |

为什么不用纯 XX：占位符要占住真实字宽，2–4 个字才能验证字号、断行和留白；纯 XX 会让样片失真成一张没填完的表单。「某某」既守住字宽，读起来也是"待填"，不是"乱码"。

**不要退回生造专名**（早前版本用过的那类"生造双字 + 行业词"）—— 生造词仍有极小概率与真实主体重名，占位符的概率是零。

出厂前必跑词表检查，返回 0 才允许渲染：

```bash
python tools/check_names.py src/u/template-demo.ts
```

**2. 构图统一居中**
贺报是庄重场合，标题 / 副标 / 数字 / 人名一律居中于 `x=88 w=904` 版心。原来按 `arr` 奇偶做左右交替，导致半数据模板看着"歪向一边"，已全部改为居中。

**3. 装饰线不得与文字抢位**
内框、分隔线、套色圆、遮幅都算装饰。凡落在品牌行（104–143）、页脚轨（1704–1735）、脚注（1824–1858）三条带上的装饰，一律挪开；皮肤可通过 `safeRight` / `footnoteBottom` 让布局主动避让。

**4. 暗底不压死**
`mode:'dark'` 底色明度不低于 8%，`Page` 叠加 6% 顶光、暗角上限 22%；次级文字 alpha 不低于 `dim 0.84` / `faint 0.5`。

## 合规

- 所有数字必须带口径与时间范围，写在 `footnote`；
- 成片默认用于内部表彰与品牌传播，对外投放前请按行业要求替换合规小字（金融 / 医疗 / 教育尤其注意）。
