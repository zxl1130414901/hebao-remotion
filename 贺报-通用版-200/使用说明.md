> 13 套视觉体系 × 73 种叙事结构 ｜ 1080×1920 · 8s · 60fps · 带音效配乐 ｜ 任意行业通用

## 三幕节奏与第二幕底纹

第三批的 43 个骨架都是"实物/档案/仪器"的空间隐喻，它们的图形只出现在第一幕（0–3.4s）。
如果第二幕（3.5–6.4s，数据页）把图形整块撤掉，8 秒里就有近 3 秒和任何一套模板长得一样——
横向翻看又会变回"同一个模子换底色"。所以第三批的第二幕统一加了一层**低透明度骨架底纹**：

- 账本留下横格与红竖线、日历留下格阵与红圈、棱镜留下入射光与五条光谱、沙漏留下上下玻璃体……
- 底纹有效不透明度约 0.15–0.2，只画结构线，不塞文字，中央再压一层底色渐变，保证数字与三列事实项始终压得住
- 只存在于第二幕，第一幕（真图形）与定版页（EndCard）不受影响

想调强弱：改 `src/u/layouts3/motif.tsx` 末尾 `opacity: s.mode === 'dark' ? 0.34 : 0.3`，
数值越大底纹越明显；设成 0 即回到纯数据页。

## 换成你自己行业的内容

文案全部住在 `content/demo.json`（200 条，键 `u01`–`u200`），**改文案不需要碰任何代码**。三条路，按顺手程度选：

### 0 · 直接在画廊里改（推荐）

1. 双击 `启动出片台.bat`（黑窗口别关，它会自动打开 `http://127.0.0.1:8788`）
2. 打开 `gallery.html`，鼠标移到任意一张卡片 → 右上角出现 **「✎ 改这套」**；或点卡片进详情，底部也有 **「改这套文案 · 直接出片」**
3. 弹层里就是出片台，已自动定位到这一支：左边选模板、右边填内容，点「生成视频」
   - 表单会随版式变化：巨字 / 人物 / 数字版出「核心数字」，榜单版出「榜单行」，历程版出「三节点」
   - 「存为模板文案」把当前内容写回 `content/demo.json`，下次打开就是这份
   - 成片落在工程目录 `studio-out/`，弹层内可直接播放与下载
   - **只渲你选中的这一支**，其它 199 支原样不动，单支约 40–90 秒

> 弹层里若提示「出片台没在运行」，说明那个黑窗口没启动或已关闭——回去双击 `启动出片台.bat`，等服务起来后弹层会**每 2.5 秒自动重试连上**，不用刷新。

**双击 `启动出片台.bat` 报错 / 一闪就关？** 按顺序排查：

| 黑窗口里看到的提示 | 原因 | 怎么办 |
|---|---|---|
| 一堆 `'xxx' 不是内部或外部命令`、路径变成乱码 | 旧版本脚本用 UTF-8 保存，中文 Windows 的 `cmd` 按 GBK 读，行错位后命令全乱 | **已修复**（脚本改用 GBK 编码保存），重新复制一次本目录的 `启动出片台.bat` 即可 |
| `找不到出片台工程目录` | `hebao-remotion` 没和本文件夹放在同一层 | 把两个文件夹都放在 `F:\workbuddy\` 下，或把工程目录移回来 |
| `没找到 Node.js / npm` | 没装 Node，或装了但没进 PATH | 装 [Node.js 18+](https://nodejs.org)，装完**重开窗口** |
| `npm error code ENOENT ... package.json` | 脚本没切到工程目录就跑了 npm（旧版症状） | 同上，用新的 bat |
| 窗口停住不动、浏览器没弹 | 首次打包要 10–20 秒，正常等待即可；超过 1 分钟看有没有红色报错 | 手动打开 `http://127.0.0.1:8788` |
| `EADDRINUSE 8788` | 上一次的服务没关干净 | 关掉旧黑窗口；或 `netstat -ano \| findstr 8788` 找 PID 后 `taskkill /PID xxx /F` |

> 新版脚本无论走到哪一步失败都会停在 `请按任意键继续`，不会再闪退，可以直接把窗口里的红字截图发过来。

> **为什么改文案一定要渲染、而不能"直接编辑"？**
> 成片是 mp4，文字已经烧成像素，没有文本层，改字只能重画这一帧。所以"可编辑"指的是**文案和数据可编辑**，不是成片可编辑。区别只在渲几支：改一支 ≈ 1 分钟；只有动了公共层（版式、皮肤、占位符规则）才需要全量重渲 200 支（约 1.5 小时，分三段跑）。

## 渲染纪律

| 参数 | 值 | 说明 |
|---|---|---|
| `--concurrency` | 3–4 | 本机 22 核实测：并发 6 以上不再提速，反而更容易 OOM |
| 浏览器复用 | 每 4 支重启 | 复用 Chrome 会累积内存，跑到 8 支以上必然崩，脚本已按批重启 |
| `--crf` | 19 | 质量 / 体积平衡点 |
| 单支耗时 | 40–90s | 8s × 60fps = 482 帧，重装饰皮肤偏慢 |
| 分辨率 | 1080×1920 | 竖屏，抖音 / 视频号 / 朋友圈直接可用 |

批量：工程目录执行 `node tools/render65.mjs <id...>`（单次打包 + 分批重启浏览器），或 `bash tools/render65.sh`（纯串行壳，慢但最稳）。

**只改文案不用清缓存、也不用全量重渲**：文案在 `content/demo.json`，出片台走 props 覆盖，只渲你选的那一支。

**改了版式 / 皮肤 / 组件才要清缓存并全量重渲**：`rm -rf node_modules/.cache/remotion node_modules/.cache/webpack`，否则视频会命中旧打包产物（静帧是新的、成片是旧的）。

## 演示内容与视觉规范

这一版延续四条硬规则，任何二次创作都应遵守：

**1. 专名一律用占位符，画面零真实信息**

演示片里不出现任何真实、或看着像真实的人名、机构、医院、商场、城市、赛事、奖项。全部换成占位符，客户一眼就知道"这一格归你填"：

| 类型 | 占位写法 | 示例 |
|---|---|---|
| 机构 / 项目 | 某某 + 行业词 | 某某科技 / 某某资本 / 某某医院 / 某某壹号 |
| 单人姓名 | 某某（保留头衔） | 某某 · 区域总监 / 某某 博士 |
| 榜单多行 | 类别 + 甲乙丙丁戊 / A–E | 门店 A / 医院 B / 选手 C / 直播间 D |
| 城市 / 场馆 | 某某市 / 某某 + 场馆；并列时用甲市–戊市 | 某某市 / 某某大剧院 / 甲市 |
| 赛事 / 奖项 | 某某联赛 / 年度大奖 | 某某联赛 S10 / 年度剧目大奖 |

为什么不用纯 XX：占位符要占住真实字宽，2–4 个字才能验证字号、断行和留白；纯 XX 会让样片失真成一张没填完的表单。「某某」既守住字宽，读起来也是"待填"，不是"乱码"。

**不要退回生造专名** —— 生造词仍有极小概率与真实主体重名，占位符的概率是零。

出厂前必跑词表检查，返回 0 才允许渲染：

```bash
python tools/check_names.py            # 默认扫 content/demo.json
```

**2. 构图统一居中**
标题 / 副标 / 数字 / 人名一律居中于 `x=88 w=904` 版心；只有明确要做镜像构图的骨架（`arr=1`）才左右翻转，翻转的是**图形**，文字仍居中。

**3. 装饰线不得与文字抢位**
内框、分隔线、套色圆、遮幅都算装饰。凡落在品牌行（104–143）、页脚轨（1704–1735）、脚注（1824–1858）三条带上的装饰，一律挪开。

**4. 暗底不压死**
`mode:'dark'` 底色明度不低于 8%，`Page` 叠加 6% 顶光、暗角上限 22%；次级文字 alpha 不低于 `dim 0.84` / `faint 0.5`。

## 合规

- 所有数字必须带口径与时间范围，写在 `footnote`；
- 成片默认用于内部表彰与品牌传播，对外投放前请按行业要求替换合规小字（金融 / 医疗 / 教育尤其注意）。
